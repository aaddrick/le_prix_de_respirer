# Testing

There is no test framework and no CI. A wrong bracket still produces a
reasonable-looking number, so looking at the page is not a check. Use the
steps below and say which ones you ran. How to write a check that can fail is
in [test methodology and coverage](learnings/test-methodology-and-coverage.md).

## 1. The Node check (calculation and data changes)

`js/taxCalculator.js` and the modules in `js/data/` import cleanly in Node 18
or later. Run these from the repo root.

### Reference scenario

Employment income 75,000, no other deductions, in four jurisdictions:

```bash
node --input-type=module -e "
import { TaxCalculator } from './js/taxCalculator.js';
const t = new TaxCalculator();
console.log('prov federal provincial payroll takeHome');
for (const p of ['on', 'qc', 'bc', 'ab']) {
  const r = t.calculate({ employmentIncome: 75000, province: p });
  console.log(p, r.federal.net.toFixed(2), r.provincial.net.toFixed(2),
    r.payroll.total.toFixed(2), r.totals.takeHome.toFixed(2));
}"
```

Expected at the time of writing:

### How the figures were checked

The figures above were generated by running the engine with the commands
shown. They were then compared with an independent computation: CRA's Payroll
Deductions Online Calculator for federal tax, provincial tax and payroll where
it covers them, and a separate script that re-implements the CRA payroll
formulas (T4127) from constants transcribed from the published tables, without
importing `js/data/`. Method: the same income at several levels in every
jurisdiction, compared line by line (federal tax, provincial tax, each payroll
item). Federal tax and payroll agree to the cent. Provincial tax for `on`, `ab`
and `bc` agrees within a dollar or two, which is the rounding between an annual
computation and a per-pay one. `bc` uses the annual value of its mid-year
changes, because the payroll calculator's pre-July run uses the January value
(see [tax-rules.md](tax-rules.md)).

`qc` is the least-checked row. CRA's calculator has no Quebec provincial tax,
so its provincial figure comes only from a separate computation of Revenu
Quebec's rules, and some of the Quebec values carry `flags` in `js/data/qc.js`.
In that computation the basic personal amount already accounts for QPP, EI and
QPIP, so there is no separate provincial credit for them, and the engine
matches it. Don't change `qc` to match another calculator without a Revenu
Quebec source.

Those cross-check files are not part of the repo. When you change a rate,
repeat the method yourself: take the published table, compute the figure by
hand or in a throwaway script that does not import `js/data/`, and compare.
A figure that matches only the engine's own output proves nothing.

### Data and failure checks

Every module loads, carries a year and sources, a missing required field
throws, and a changed rate moves the result. The list of modules is asserted
non-empty first, so a broken import fails instead of passing over nothing:

```bash
node --input-type=module -e "
import data from './js/data/index.js';
import { TaxCalculator } from './js/taxCalculator.js';
const names = ['fed', 'payroll', ...data.provinceCodes];
if (data.provinceCodes.length === 0) throw new Error('no provinces loaded');
for (const c of names) {
  const m = data[c] ?? data.provinces[c];
  if (!m || m.year !== 2026 || !m.sources?.length) throw new Error(c + ' missing or unsourced');
}
const bad = structuredClone(data);
delete bad.provinces.on.credits.basicPersonalAmount;
let threw = false;
try { new TaxCalculator(bad).calculate({ employmentIncome: 75000, province: 'on' }); } catch { threw = true; }
const mut = structuredClone(data);
mut.provinces.on.brackets[0][1] += 0.01;
const base = new TaxCalculator().calculate({ employmentIncome: 75000, province: 'on' }).totals.takeHome;
const moved = new TaxCalculator(mut).calculate({ employmentIncome: 75000, province: 'on' }).totals.takeHome;
console.log('modules loaded:', names.length, '| missing field throws:', threw, '| rate change moves take-home:', moved !== base);"
```

Expected:

```
modules loaded: 15 | missing field throws: true | rate change moves take-home: true
```

### Scenario A/B and all-provinces checks

The Take-home tab's A/B difference and the all-provinces table are both built from
`calculate()` and `compareAll()`. This asserts that each `compareAll()` row
equals the matching `calculate()` figure, and shows the difference the A/B
table would print for Ontario against Alberta at the same salary:

```bash
node --input-type=module -e "
import { TaxCalculator } from './js/taxCalculator.js';
const t = new TaxCalculator();
const rows = t.compareAll({ employmentIncome: 75000 });
if (rows.length === 0) throw new Error('compareAll returned no rows');
const mismatched = rows.filter(r =>
  r.takeHome !== t.calculate({ employmentIncome: 75000, province: r.province }).totals.takeHome);
const a = t.calculate({ employmentIncome: 75000, province: 'on' }).totals.takeHome;
const b = t.calculate({ employmentIncome: 75000, province: 'ab' }).totals.takeHome;
console.log('rows:', rows.length, '| rows that differ from calculate():', mismatched.length,
  '| ab minus on take-home:', (b - a).toFixed(2));"
```

Expected:

```
rows: 13 | rows that differ from calculate(): 0 | ab minus on take-home: 435.68
```

The calculator and the data must stay free of the DOM. This prints nothing when
it is clean:

```bash
grep -nE '\b(document|window)\.|localStorage' js/taxCalculator.js js/data/*.js
```

A hit means the Node check will fail with `document is not defined`.

If you change a bracket or rate on purpose, these figures change. Recompute
them, check them against the published table as above, and update the blocks in
the same commit. If you leave them stale, the next contributor will "fix"
correct code.

## 2. The manual pass (UI changes)

Serve the site (see [getting-started.md](getting-started.md)) and keep the
console open. A clean run shows no errors.

- On the Setup tab, enter 75,000 in Scenario A with `on` and in Scenario B with
  `qc`. Open the Take-home tab and check each take-home against the reference table, and
  that the difference card equals B minus A. Check that each slider and number
  box stays in sync both ways, in both scenarios.
- Turn the compare switch off. Scenario B, its Take-home column, the difference
  card and the A/B switch above the math tabs should all disappear, and the
  figures for A should not change.
- Change either province. Every figure on every tab should update, including
  the provincial math tab and the payroll math tab (QPP and QPIP appear for
  `qc`).
- Open every tab. The math tabs show the scenario picked in the A/B switch.
- Open the All provinces tab at the same income. Each row should equal the
  take-home in the reference table, and clicking a column header should
  re-sort. Check the sales-tax table shows a source link per province.
- Check the "Verify these numbers" section and the links next to each rate. A
  rate with no link, or a link that opens a page that does not state the value,
  is a bug in the data module's `sources`.
- Check that a jurisdiction with a flag, such as `mb`, shows it on its math tab.
- Try an income of 0 and a very high one, in a province with a surtax and in
  one with none. The page should show no error.
- Toggle the theme, reload, and confirm the theme sticks.
- Narrow the window to phone width. The CSS is mobile first.
- If you touched a shared module, click every button on `example.html`.
